```text

│  ├─ 국가: KR / CZ / US
│  ├─ 원천과 operation

├─ 2. 현재 채용 검색

│  ├─ 국가

│  │  └─ CZ 공공: 공공행정 직무 / ARES 확인 법적형태 / 소유부문 미확인
│  ├─ 기관·기업 유형과 법적 형태
│  ├─ 직종: 키워드 / provider label / 직업분류 코드
│  ├─ 위치
│  ├─ 고용·근무 형태
│  ├─ 급여: 통화 + 기간 + basis가 같은 그룹 내부만
│  ├─ 요건: 필수 / 우대 / 교육 / 언어 / 기술 / 자격증
│  ├─ 결과 미리보기: 엄격일치 / 검증불가 / 불일치 / 충돌
│  └─ 실행 → 설명 → CSV/XLSX
├─ 3. 채용 동향 분석
│  ├─ snapshot 이력 충족 여부
│  ├─ 기간·주기

│  ├─ 기관/기업 cohort와 identity 품질
│  ├─ 직종·산업
│  ├─ 지표: 신규 / 활성 stock / 종료 / 모집인원 / 급여분포 / 요건 빈도
│  ├─ 비교 기준: 이전기간 / 국가 / 기관군 / 직종군

├─ 4. 기업·기관 분석
```

## 3. 현재 채용과 동향 분석의 분리 계약

| 구분 | 현재 채용 검색 | 채용 동향 분석 |
|---|---|---|
| 기본 단위 | 하나의 기준시각에 활성인 공고 | 동일 정의로 반복 수집된 snapshot 시계열 |
| 필수 시각 | `collected_at`, `active_as_of` | 각 snapshot의 `collected_at`, 관측 구간·주기 |
| 기본 지표 | 일치 공고 수, 기관 수, 요건 수, 모집인원 | 신규·유지·종료 공고, stock 변화, 급여·요건 분포 변화 |
| 분모 | 조회 원천 반환량과 CIL 정규화/활성 행 수 | 기간별 원천 coverage와 identity 연결 가능 행 수 |
| 허용 추론 | 현재 공개된 채용 수요 | 관측 기간 내 공개 채용 수요의 변화 |
| 금지 추론 | 실제 채용 완료 인원, 전체 노동시장 규모 | 단일 snapshot의 추세화, coverage 변화의 경기효과 오인, 인과 추론 자동 승격 |

현재 보유한 2026-09-13 snapshot은 현재 채용 검색에는 사용할 수 있다. 그러나 반복 snapshot 이력이 없으므로 동향 분석의 실제 수치 산출에는 아직 부적격이다. 트리는 이때 지표 선택을 비활성화하고 `insufficient_snapshot_history`와 필요한 최소 수집 조건을 표시해야 한다.

## 4. 단계별 활성화 규칙

1. 각 노드는 이전 선택으로 남은 행에서 계산한 고유값·행 수·provider coverage를 표시한다.
2. `filterable`이고 근거가 있는 값만 선택한다. `display-only`, `unavailable`, `forbidden`은 이유와 함께 보이되 profile에 넣지 않는다.
3. MPM `type01/type02`, MPSV·ARES 코드처럼 namespace가 다른 값은 원시값을 합치지 않는다. 검증된 crosswalk가 있을 때만 공통 semantic value를 추가한다.
4. `ownership_sector`, `public_institution_type`, `legal_form`, `industry`, `market_status`는 독립 축이다. 기관명·공고 source·legal form 하나로 다른 축을 추정하지 않는다.
5. 급여는 `currency + period + basis` signature가 완전하고 같은 그룹에서만 필터·정렬한다. 월급과 시급, KRW와 CZK는 환율·연환산 계약 없이는 합치지 않는다.
6. 사용자가 뒤로 이동하면 하위 선택과 facet count를 재계산한다. 0건 분기는 실행 전에 보이고, 강제로 선택하면 `no_match`가 아니라 `invalid_selection`으로 설명한다.
7. 최종 실행 전 선택 manifest, 실제 command/profile, 원천·snapshot 시각, 예상 분모를 미리 보여 준다.

## 5. 범위 개정 결정과 cohort

| 결정 | 결정할 내용 | 권장안 |
|---|---|---|
| D-11 | live refresh와 snapshot 재사용·페이지네이션·최신성 계약 | provider operation별 수집 후 불변 snapshot으로 검색 |
| D-12 | 현재 채용과 동향 분석의 모드 경계 | 입력·지표·부적격 사유가 다른 독립 모드 |
| D-13 | 한국·체코 공공부문 기관 identity | MPM↔ALIO, MPSV IČO↔ARES의 근거 결합과 미연결 보존 |
| D-14 | 화살표 기반 점진 facet 트리 | 실제 남은 행에서 값·count·disabled reason을 재계산 |
| D-15 | 현재 채용 검색 실행·결과 계약 | 활성 기준시각과 4상태 결과·분모·coverage를 함께 반환 |
| D-16 | 채용 동향 시계열 계약 | 반복 snapshot과 정의 고정 전에는 분석불가 처리 |
| D-17 | 선택 세션·설명·내보내기 재현성 | manifest에서 동일 profile·결과 근거를 재생 가능하게 결속 |

신규 cohort는 C-07~C-12의 6개다. C-07 수집 기반 → C-08 identity → C-09 모드·트리 → C-10 현재 채용 / C-11 동향 분석 → C-12 provenance 전달 순서로 구성한다. 기존 C-01~C-06 구현은 보존하지만, 새 범위는 별도 승인·PREPARE 전까지 구현 권한이 없다.

## 6. 완료 기준

- 사용자가 최상위에서 `현재 채용 검색`과 `채용 동향 분석`을 혼동하지 않고 선택한다.
- 각 다음 메뉴는 선택된 provider/snapshot에 실제 존재하며 filterable인 값만 활성화한다.
- KR 공공기관과 CZ 공공행정/법인 형태가 출처별 의미를 잃지 않고 연결된다.
- 현재 검색은 기준시각·분모·일치/검증불가/불일치/충돌 개수를 표시한다.
- 동향 분석은 최소 반복 snapshot·coverage 기준 미충족 시 수치를 만들지 않는다.
- 최종 선택이 profile, command, snapshot hash, 결과 및 export manifest로 재현된다.
